Защищённые базы

Перезапись этих баз выполняется только после подтверждения администратором (пользователем с полным доступом): пользователь отправляет запрос, и восстановление начнётся, когда администратор его подтвердит. Подтверждающие из внутренних групп такие запросы подтвердить не могут. Администраторы восстанавливают защищённые базы сразу. Защита касается тех, у кого эта база есть в списке разрешённых (лично или через группу); остальные её в списке не видят.

Пользователи

Список пополняется автоматически при первом входе пользователя из Active Directory. Пользователь с ролью «Копии и восстановление» может восстанавливать только в отмеченные базы (лично или через группы). Пока ничего не отмечено, список пуст, но создать новую базу можно — через запрос на подтверждение. Для пользователей с полным доступом ограничений нет.

Внутренние группы

Группы существуют только в этом приложении и не связаны с группами LDAP. Группа может разрешать восстановление в выбранные базы и/или подтверждать запросы на создание новых баз. Пользователи с полным доступом тоже могут подтверждать запросы. Участники выбираются из списка пользователей, поэтому человек должен хотя бы раз войти.

Хранилище копий по умолчанию

Может быть и смонтированной на самом сервере SQL шарой. Службе SQL Server нужны права на запись.
Пишет сам SQL Server от имени учётной записи своей службы (SQL Server на Windows) — ей нужны права на запись в шару. Логин и пароль SMB здесь не задаются.
Нужен HTTPS с сертификатом, которому доверяет сервер SQL. Бакет должен существовать. Файл копии не может быть больше 100 ГБ.
Проверка делает небольшую копию системной базы model в выбранное место (файл mssql_backup_web_write_test.bak, перезаписывается).

HTTPS-сертификат

1. Запрос сертификата (CSR) для центра сертификации

Закрытый ключ создан и остаётся на сервере (в браузер не передаётся). Отправьте CSR в центр сертификации домена, например Microsoft AD CS: веб-страница /certsrv → «Запрос сертификата» → «Расширенный запрос» → вставьте текст CSR, шаблон «Веб-сервер»; или certreq -submit -attrib "CertificateTemplate:WebServer" mssql-backup.csr. Получите сертификат в формате Base64 (.cer / PEM).

2. Установка выданного сертификата

Можно загрузить цепочку (сертификат сервера + промежуточные центры) — подходящий порядок будет выбран автоматически; корневой сертификат в цепочку не включается.
После установки nginx перенастраивается и перезагружается автоматически (отдельная служба mssql-backup-tls); прежняя конфигурация возвращается, если проверка не прошла. Страница откроется по новому адресу HTTPS.

Сообщение уходит, когда задача из очереди завершилась: копия создана или восстановление выполнено (или закончилось ошибкой).

О чём сообщать

E-mail

Telegram

Прокси используется только для Telegram (системные переменные HTTP_PROXY игнорируются). Типичные порты: HTTP — 3128 или 8080, SOCKS5 — 1080. Для SOCKS5 имя api.telegram.org разрешает сам прокси.
Создайте бота у @BotFather и скопируйте токен. Добавьте бота в нужную группу/канал (в канале — администратором) или напишите ему сами. Id чата можно узнать, написав в чат и открыв https://api.telegram.org/bot<токен>/getUpdates. Серверу нужен выход на api.telegram.org по HTTPS.

Bitrix24 (облако)

В Bitrix24: Разработчикам → Другое → Входящий вебхук, право «Чат и уведомления (im)». Скопируйте URL вида …/rest/1/код/. Бот не нужен: сообщение отправляется от имени владельца вебхука (создайте для этого отдельного пользователя, например «Backup»). Получатель: личный чат — id пользователя; обычный чат — chat + номер (im.chat.get); чат рабочей группы/проекта — sg + номер группы. Отправитель должен быть участником чата или группы.

Webhook (произвольный)

POST с JSON {"text": "…", "event", "database", "job", "user", "status"} — подходит для Slack, Mattermost, Rocket.Chat и своих обработчиков. URL часто содержит токен, поэтому после сохранения не показывается.

Авторизация LDAP

Локальный администратор (из файла настроек сервиса) входит всегда, даже при неверных настройках LDAP.
{username} заменяется введённым логином.

Группы доступа (DN группы)

Роль определяется по атрибуту memberOf пользователя (прямое членство, вложенные группы не раскрываются). Если пользователь в нескольких группах, берётся высшая роль; вне этих групп войти нельзя.

Проверка

Пользователь

Три независимых доступа (личные + из групп): создание копий — для каких баз можно делать копии; источники — чьи копии можно брать при восстановлении; куда восстанавливать — какие существующие базы можно перезаписывать. Что не отмечено, того для пользователя нет: в «Создать копию» база не показывается, копии не попадают в «Восстановить копию», в базу нельзя восстановить.

Группа

Три независимых доступа для всех участников группы: создание копий, источники восстановления (чьи копии можно брать) и базы, которые можно перезаписывать.
